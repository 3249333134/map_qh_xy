## 一、项目定位与核心愿景

### 1.1 一句话定位

构建一款融合**地图可视化**、**兴趣社交**与**本地服务**的新型社交平台，打造「以地图为界面、以频道为结构、以内容为纽带」的创新社交模式。

### 1.2 核心愿景

- **探索世界**：让用户走出去探索地图、探索世界
- **感受世界**：足不出户也能感受世界律动，跨越时空看到万般风景
- **收藏记忆**：把每一段旅程变成永恒，让足迹成为数字资产

### 1.3 价值主张

打破传统社交平台以时间线或联系人为核心的结构，强调「**人—内容—位置**」的有机互动，让地图成为新一代社交网络的基础设施，承载用户足迹、动态卡片、即时互动、事件感知的社交场景底座。

### 1.4 长远视角

项目不仅是 App，更是未来数字场景经济的基础设施：

| 维度 | 目标 |
|------|------|
| **2C 消费者** | 沉淀足迹、表达情绪、发现同好 |
| **2B 商家** | 景区/展会/商圈构建用户阵地 |
| **2G 政府** | 城市管理、文化宣传、数字文旅广泛传播 |

## 二、核心创新点

### 2.1 空间社交范式（核心创新）

**从「时间线」转向「空间线」**

传统社交平台以时间线（Feed）或联系人（社交图谱）为核心组织内容，足迹首创以**地图空间**为社交入口：

- 地图不只是导航工具，而是社交界面
- 内容天然绑定地理位置，形成空间维度表达
- 用户在地图上「漫游」而非「滑动」，探索感替代刷屏感

```
传统社交：  时间线 → 内容 → 人
足迹模式：  地图空间 → 内容 → 人 → 服务
```

### 2.2 频道化结构体系

借鉴 Discord 的「类别—频道—子频道」三级结构，构建三维频道架构：

| 频道类别 | 说明 | 示例 |
|---------|------|------|
| **地理位置类** | 按城市→商圈→副本层级递进 | 成都 → 春熙路 → 某商场副本 |
| **兴趣主题类** | 按兴趣领域分类，支持子频道 | 摄影 → 街拍 / 风光 / 人像 |
| **功能服务类** | 服务咨询与预约 | 插画定制 → 预约咨询频道 |

**创新价值**：频道即场景，进入不同频道即切换不同社交语境，所见即所得。

### 2.3 副本机制

进入特定区域（景区/商超/活动场地）后自动切换至「**副本地图**」：

- 副本内独立探索，屏蔽外部干扰
- 专属锚点、专属内容、专属服务
- 支持楼层切换（室内导航场景）
- 退出副本返回全局地图

**创新价值**：将游戏化「副本」概念引入地图社交，增强沉浸感和场景聚焦。

### 2.4 信标共建体系

类似 Wiki/GitHub 的共建机制：

```
用户发起打卡点 → 3人点赞审核通过 → 纳入公共地图
                                        ↓
                              优质信标接入导览系统
                                        ↓
                              形成地点维基百科
```

**创新价值**：用户从内容消费者变为地图共建者，实现地图内容的自生长。

### 2.5 内容即服务

服务卡片与内容卡片结构统一，实现「**内容即服务、服务即创作**」转化闭环：

- 用户发布的打卡内容 → 自然转化为地点推荐
- 商家发布的服务 → 以卡片形式融入内容流
- 个人技能服务 → 场景化表达，建立个人频道实现变现

**创新价值**：消除内容与服务边界，降低商业化突兀感。

### 2.6 去中心化个人服务

鼓励每位用户将能力、特长「场景化表达」：

- 插画定制、城市导览、摄影跟拍
- 舞蹈陪练、塔罗占卜、造型设计
- 兼职 coser、LiveHouse、创意市集摊主

**创新价值**：人人皆可成为服务提供者，激活长尾经济。

### 2.7 AI 全链路赋能

| AI 能力 | 应用场景 |
|---------|---------|
| **AI 搜索** | 多模态问答 + 内容召回，支持自然语言输入（如「附近有什么适合拍照的地方」） |
| **AI 辅助创作** | 文案生成、场景模板、年度足迹热力图、创作成就证书 |
| **AI 内容审核** | 初筛 + 用户举报 + 人工复审三重机制 |
| **AI 推荐算法** | 兴趣匹配度(40%) + 距离权重(30%) + 互动历史(20%) + 内容新鲜度(10%) |

### 2.8 图层开源属性

图层与卡片具备开源属性，支持定制化/客制化：

- 用户可在地图发布卡片
- 卡片可在广场发表
- 被兴趣雷达捕获
- 支持第三方图层接入

### 2.9 时间胶囊

内容可设置「公开条件」：

- **到某地可见**：到达指定地理位置后解锁内容
- **某时间内可见**：设定时间后自动公开

**创新价值**：将时间与空间作为内容解锁条件，创造期待感和探索动力。

### 2.10 多人协作共创

- 轨迹编辑支持多人协作
- 地图点位共创（信标共建）
- 基于 CRDT 的实时协作编辑

## 三、差异化竞争优势

### 3.1 竞品对比

| 维度 | Foursquare | Zenly | 小红书附近 | 百度地图短视频 | **足迹** |
|------|-----------|-------|-----------|--------------|----------|
| 地图为核心 | 部分 | 是 | 否 | 否 | **是** |
| 持续社交互动 | 缺乏 | 有 | 弱 | 无 | **完整** |
| 内容沉淀 | 弱 | 无 | 有 | 弱 | **强（足迹）** |
| 服务闭环 | 无 | 无 | 部分 | 无 | **完整** |
| 频道化结构 | 无 | 无 | 无 | 无 | **有** |
| 副本机制 | 无 | 无 | 无 | 无 | **有** |
| 商业模式 | 广告 | 单一 | 电商 | 广告 | **多元** |

### 3.2 核心壁垒

1. **空间社交范式首创**：首个真正打通地图+内容+服务+社交互动的完整平台
2. **频道化内容组织**：三维频道架构形成独特内容结构壁垒
3. **信标共建生态**：用户共建形成地图内容网络效应
4. **副本机制**：游戏化地图社交，提升沉浸感与留存
5. **内容即服务闭环**：内容与服务无缝转化，降低商业化摩擦

## 四、设计理念

### 4.1 六大核心设计理念

#### 理念一：空间即界面，内容即连接

以地图为核心载体构建沉浸式探索体验。地图不是工具栏的附属功能，而是用户进入应用后的第一视觉焦点和操作起点。

```
┌─────────────────────────┐
│      地图全屏背景         │  ← 视觉主体
│   ◆    ◇       ◆        │  ← 锚点（内容入口）
│        ◇                │
│  ┌───────────────────┐  │
│  │  搜索栏 + 标签栏    │  │  ← 轻量导航层
│  ├───────────────────┤  │
│  │                   │  │
│  │  瀑布流卡片区域     │  │  ← 内容悬浮层
│  │  ┌──┐  ┌──┐       │  │
│  │  │卡│  │卡│       │  │
│  │  └──┘  └──┘       │  │
│  └───────────────────┘  │
└─────────────────────────┘
```

#### 理念二：频道即场景，对话即连接

打破传统「联系人+私聊」线性沟通模式。进入不同频道即进入不同社交场景，对话在场景中自然发生。

#### 理念三：场景驱动创作

内容创作从「发帖」变为「我在某地、某频道、某服务场景中自然想记录或表达」。创作入口随场景出现，降低创作门槛。

#### 理念四：结构统一，流转自由

所有 UGC 以「卡片」形式统一结构呈现，具备图文/视频、地理位置、时间节点、发布频道、服务关联、互动数据等维度。卡片可被收藏、转发、置顶，自动纳入内容流推荐、地图标注推送等分发系统。

#### 理念五：所见即所得

地图标点与服务/内容卡片一一对应。用户在地图上看到的每一个锚点，都对应一张可交互的内容卡片，消除信息断层。

#### 理念六：一键化编辑

不断简化使用逻辑，降低学习成本，让用户实现傻瓜式分享。发布流程结构化引导，支持草稿与预约。

### 4.2 设计原则

| 原则 | 说明 | 应用示例 |
|------|------|---------|
| **地图优先** | 地图始终可见，操作不脱离地图语境 | 卡片面板可拖拽，地图始终露出 |
| **内容悬浮** | 内容卡片悬浮于地图之上，不遮挡探索 | 半透明卡片背景 + 轻投影 |
| **渐进披露** | 信息分层展示，按需展开 | 卡片摘要 → 详情页 → 频道深度 |
| **场景感知** | UI 根据用户位置和场景动态变化 | 进入副本自动切换地图模式 |
| **轻量交互** | 减少操作步骤，一键直达 | 地点卡片直接显示导航/预约按钮 |

### 5.6 卡片视觉设计

遵循小红书风格「清爽留白 + 高对比 + 轻量装饰」：

- **无外框**：去掉卡片边框，纯内容卡片
- **轻投影**：仅使用轻微阴影让卡片「悬浮」
- **图片优先**：图片占卡片上 2/3，文字区留白充足
- **信息分层**：标题 → 作者 → 互动数据，层级分明
- **标签内敛**：标签放图片右下角，不遮挡主体

## 六、交互设计要领

### 6.1 地图交互

#### 锚点系统（五大类型）

| 锚点类型 | 视觉特征 | 交互行为 |
|---------|---------|---------|
| 互动地标锚点 | 金色徽章 + 360°角标 | 点击进入副本/全景 |
| 兴趣 POI 锚点 | 彩色标签 + 呼吸动画 | 点击弹出卡片预览 |
| 活动锚点 | 紫色气泡 + 倒计时 | 点击进入活动详情 |
| 基础内容锚点 | 蓝色大头针 + 新评论红点 | 点击弹出卡片预览 |
| 普通定位锚点 | 灰色定位标 + 未探索蒙层 | 点击发起探索 |

#### 智能图层系统

```
基础渲染层：天气粒子 / 昼夜色调 / 热力图
    ↓
功能筛选层：标签聚类 / 点线面块图层
    ↓
次级世界图层：副本锚点 3D 图标 + 楼层切换
```

#### 地图-内容双向联动

| 用户操作 | 地图响应 | 卡片响应 |
|---------|---------|---------|
| 点击地图锚点 | 视角平滑聚焦 | 对应卡片高亮 + 面板上滑 |
| 点击卡片上半区 | 视角聚焦到卡片位置 | 进入详情页 |
| 点击卡片下半区 | 视角聚焦到卡片位置 | 卡片高亮，不跳转 |

### 6.2 卡片面板交互

#### 三档高度 + 自由悬停

| 档位 | 高度比例 | 显示内容 |
|------|---------|---------|
| 最小态 | 18% | 拖拽条 + 搜索栏 + 标签栏 |
| 半屏态 | 50% | 标签栏 + 部分瀑布流卡片 |
| 全屏态 | 66.6% | 完整瀑布流卡片 |

- 拖拽过程中地图透明度动态调整
- 拖拽结束后**自由悬停**，不强制吸附
- 最小态下点击面板任意位置回到半屏态

#### 瀑布流卡片交互

- 双列交错布局，高度自适应内容
- 上滑加载：底部显示骨架屏占位
- 下拉刷新：触发刷新动画
- 空状态：「暂无内容，去发布第一条动态吧」+ 引导按钮
- 骨架屏：加载时显示占位骨架

### 6.3 七大卡片交互规范

| 卡片类型 | 上半区点击 | 下半区点击 | 快捷操作 |
|---------|-----------|-----------|---------|
| 普通打卡卡 | 进入详情页 | 地图定位 + 高亮 | 点赞/收藏 |
| 视频卡片 | 进入视频详情（全屏播放） | 地图定位 | 卡片内静音预览播放 |
| 文章卡片 | 进入文章详情（展开全文） | 地图定位 | 阅读量统计 |
| 地点卡片 | 进入地点详情（地图放大） | 地图定位 | 导航/预约按钮 |
| 活动卡片 | 进入活动详情 | 地图定位 | 报名按钮 |
| 服务卡片 | 进入服务详情 | 地图定位 | 预约按钮 |
| 轨迹卡片 | 进入轨迹详情（完整路线） | 地图定位 | 距离/时长展示 |

### 6.4 发布流程交互

#### 三大发布入口

```
                    「+」按钮
                       │
            ┌──────────┼──────────┐
            ↓          ↓          ↓
      发布动态     沙盒创作    IP内容发布
     （普通用户）  （创作者）   （IP方）
```

#### 发布动态流程

```
文本输入 → 图片/视频九宫格 → 添加话题 → @好友 → 添加位置 → 谁可以看 → 原创声明 → 发布
```

#### 沙盒创作流程

```
文本输入 → 图片/视频 → 沙盒分类 → 定时发布（可选）→ 预览效果 → 测试分享 → 存入草稿箱 / 发布到公开
```

#### IP 内容发布流程


## 十、运营策略要领

### 10.1 双驱动运营主线

```
内容生态驱动                    服务生态驱动
    │                              │
    ├─ 扶持创作者                   ├─ 联动本地商家
    ├─ 主题活动（城市地图征集）      ├─ 展会主办方合作
    ├─ 打卡挑战                     ├─ 文旅单位合作
    ├─ 地点故事征集                  ├─ 服务发布机制
    └─ 构建热点内容聚集              └─ 用户内容—服务—消费闭环
```

### 10.2 冷启动策略

1. **区域冷启动**：优先选择热点城市与高密度活动区
2. **地推合作**：结合地推与达人合作快速填充内容
3. **地点频道运营**：每个「地点频道」都是潜在的内容运营空间
4. **下沉扩张**：从城市 → 景区 → 社区 → 展会，自下而上扩张

### 10.3 用户增长策略

- 优化引导流程，简化内容发布与频道浏览路径
- 降低地图交互学习成本
- 一键化编辑，傻瓜式分享
- 时间胶囊机制创造自然分享动力

### 10.4 风险应对

| 风险 | 应对策略 |
|------|---------|
| 冷启动内容稀疏 | 热点城市 + 地推 + 达人合作 |
| 用户增长缓慢 | 优化引导、简化路径、一键化编辑 |
| 内容审核压力 | 信标自治机制 + AI 预审 + 人工巡查 |
| 商家入驻意愿低 | 免费入驻 + 首期佣金减免 + 流量扶持 |

### 10.5 行业趋势支撑

- 社交从「关系网络」向「内容+位置+服务」三位一体演进
- 本地生活+社交内容融合趋势显著（小红书城市笔记、地图产品引入短视频/UGC）
- 国家鼓励数字文旅、本地生活、数字地图结合，政策支持
- 未来 AR/AI/5G 发展使地图成为连接虚拟与现实入口，空间社交具备高度可拓展性
